# Ten-minute demonstration

Use a local seeded database. Every organization and event in the initial repository is fictional and visibly labeled demo data. Explain this at the start. Do not represent fixture accounts as verified Rutgers identities.

| Time | Demonstration | Evidence |
| --- | --- | --- |
| 0:00–1:00 | State the specific student discovery problem and local population. | Rutgers primary-source context; explain interview evidence still needed. |
| 1:00–2:00 | Browse as a guest, register or use the demo student, optionally select interests in AI, entrepreneurship, volunteering, photography. | Search works without profile disclosure. |
| 2:00–3:15 | Review recommendations and explanations; explore and follow an unfamiliar club. | Show mixed categories and dismiss/revisit controls. |
| 3:15–4:15 | Search for a beginner-friendly event this week; filter by campus, inspect source and exact dates. | Actual stored fixtures, explicit sample labels. |
| 4:15–5:15 | Ask a club FAQ about experience, then ask a question it cannot answer. | Cite the published FAQ; demonstrate abstention. |
| 5:15–6:00 | Save an event and export an ICS; show personal saved items. | State that interested/going expresses intent only. |
| 6:00–7:15 | Log out, log in as the demo officer, create an event for the assigned club. | Switch back to event listings and see the new event. |
| 7:15–8:00 | Edit/cancel the event, inspect aggregate analytics and role restrictions. | No individual browsing histories or public attendance list. |
| 8:00–9:15 | Explain hybrid search, the baseline, evaluation dataset and measured results. | Run the evaluation script; disclose synthetic labels and limitations. |
| 9:15–10:00 | Explain privacy controls, accessibility checks, remaining research and next decisions. | Show account deletion; summarize measured vs unmeasured outcomes. |

Record a backup video locally after verifying the complete flow. This repository does not include a fabricated demonstration recording or human research results. Prepare for questions about The Arc, real-data permissions, cold start, model limitations, officer verification, synthetic evaluation bias, and deployment security.
